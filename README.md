# 超素材をつくろう！

ドラクエ10の鍛冶(超素材)で、盤面・温度・集中力から次の一手を推奨するツール。

## 使い方

`index.html` をブラウザで開く。`style.css`・`engine.js`・`ui.js` を同じ場所に置いておくこと
(`index.html` だけを持ち出しても動かない)。

## ファイル構成

| ファイル | 役割 |
|---|---|
| `index.html` | 画面の骨組み。下の3ファイルを読み込む |
| `style.css` | 見た目 |
| `engine.js` | 計算。状態 `G`・素材データ・推奨手の評価・先読み・理想値の推定・手順の作成。画面(DOM)には触れない |
| `ui.js` | 画面。描画・テンキー・設定・保存・起動処理 |
| `mc-pool.js` | 先読みと手順作成の試行を複数の Worker に分担させる |
| `mc-worker.js` | Worker 本体。`engine.js` を読み込んで割り当てられた試行を回す |
| `tests/sim.js` | 計算エンジンの成績テスト |
| `tests/baseline.json` | 成績テストの基準 |
| `tests/power-table.js` | 温度別の威力の実測表(計算式の照合用) |

`engine.js` → `mc-pool.js` → `ui.js` の順に通常の `<script>` で読み込む。
ES Modules は `file://` で開くと読み込めないため使っていない。

先読みは端末のコア数(最大8)ぶんの Worker で分担し、計算中も画面が固まらない。
分担しても推奨手と手順は画面側だけで計算した場合と完全に同じになる。
ファイルを直接開いた場合など Worker が使えない環境では、自動で画面側の計算に切り替わる(遅く、計算中は画面が止まる)。

## 成績テスト

Node.js が必要(v22 で動作確認)。リポジトリの直下で実行する。

```
node tests/sim.js            # 基準と照合する。違えば終了コード1(4コアで約3分)
node tests/sim.js --update   # 今の結果で基準を書き換える
node tests/sim.js --games 5000 --mc 0 --preset kagayaki   # 条件を変えて成績だけ見る
```

- 各素材を乱数の種を固定して最後まで打ち、大成功率・未到達率・超過率などを出す。
  種が固定なので、エンジンを変えていなければ毎回同じ結果になる。
- **貪欲**(評価関数だけ)を300局、**先読み**(アプリと同じ選び方)を2局打つ。
  先読みは1局に15秒〜3分かかるため局数が少なく、先読みの行の大成功率は成績の比較には使えない。
  先読みの行は「挙動が1手でも変わったか」を指紋(`[xxxxxxxx]`)で検出するためのもの。
- 威力の計算式を実測表と照合する(現在248点すべて一致)。

エンジンを変更したら:

1. 動作だけを整理した(挙動は変えないつもりの)変更 → `node tests/sim.js` が「一致」になることを確かめる。
2. 推奨手を変える変更 → `--games` を増やして成績を比べ、良くなったことを確かめてから `--update` する。
   300局の大成功率の誤差はおよそ±3ポイントなので、差を見るなら数千局で比べる。
